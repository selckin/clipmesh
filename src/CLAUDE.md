# src

Per-module design notes for the clipmesh crate. Supplements `../CLAUDE.md` (overview, commands, cross-cutting invariants); the clipboard backends are in `clipboard/CLAUDE.md`.

The stack, bottom to top:

- **`transport.rs`** — Noise `NNpsk0` (`Noise_NNpsk0_25519_ChaChaPoly_BLAKE2s`) keyed by the preshared key. `handshake` splits a stream into `SendHalf`/`RecvHalf` sharing a *stateless* transport (independent per-direction nonces) so the two halves run in separate tasks. Records are chunked to Noise's 64 KiB cap, and each goes out as **one** `write_all` (length prefix encrypted into the same scratch buffer) with a single flush per logical message — `set_nodelay` is on, so a separate 4-byte header write became its own TCP segment per record, ~512 of them for a 32 MiB message. Reassembly grows the receive buffer to twice the bytes **actually delivered**, floored at a step and capped at the message: never to the length the peer merely *claimed*, which with 64 inbound slots would let a few hundred bytes of traffic pin gigabytes.
- **`protocol.rs`** — wire messages `Message::{Hello, Clip, Rules, Get, GetReply, History, HistoryReply}`, encoded with **bincode**. `Hello` carries a `PeerRole` (`Peer` or `Paster`) so a one-shot `--paste` client is never mistaken for a mesh member; `Get`/`GetReply` are the paste request/response (see `paste.rs`). `Offer = IndexMap<String, Vec<u8>>` (one clipboard state's MIME representations, kept in the source compositor's advertise/preference order end-to-end); `content_hash` (BLAKE3) sorts a copy internally so identity/dedup stays order-independent even when the compositor hands types back reordered. **`Hashed` pairs an `Offer` with its `content_hash` and is what the engine passes around** — `Hashed::new` is `content_hash`'s only production caller. The offer is immutable behind it, so a stale hash is unrepresentable: a transform that changes the content builds a new `Hashed`, one that doesn't returns its input and carries the hash forward. That is what lets the inbound path reuse the hash it already verified against the wire, and it replaces the "did this stage change anything?" flag nobody would have kept correct. The offer sits behind an `Arc`, and **terminal consumers take `into_arc`, not `into_offer`** — `Message::Clip.offer` and `Clipboard::write_offer` both carry `Arc<Offer>`. That is the whole point of the sharing: the engine's batch holds every planned action's content alive at once, so an owned terminal parameter finds refcount > 1 and deep-copies, *moving* the copy rather than removing it. serde's `rc` feature serializes the pointee, so this is byte-identical on the wire (pinned by a round-trip test). `into_offer` remains for the transform steps that genuinely take the map apart. `type_matches`, `wants_text_plain`, `TEXT_PLAIN`, `is_text` and `is_text_plain` live here too, because each is a contract *between* the two ends (the node narrows a `-t` read by `type_matches`; the client then picks out of the reply by the same rule). `History`/`HistoryReply` (v9; v10 added row numbers) carry the clipboard-history requests: `HistoryEntry` is a listing **row** and deliberately holds no payload — fifty remembered entries must not drag fifty clipboard offers across the wire, the same reason `GetWant::TypesOnly` exists — and its `age_ms` is resolved **on the node**, because an absolute timestamp would be rendered against the *client's* clock and `history list --node <peer>` would show ages skewed by the very clock disagreement the stamp guard tolerates by design. `HistoryMiss` names every reason a node has nothing to give, per `Unavailable`'s rule: a disabled history, an empty one, an unknown row or id, an ambiguous prefix, a type the entry does not offer, a selection this node does not handle, a failed write, and `Filtered(Unavailable)` for an entry that outlived the MIME rules that recorded it — "this node has no such selection" is an actively wrong answer to "every type in it is now denied". `type_matches` also honours the **generic names real `wl-paste` documents** — `-t text`, `-t image` "pick some offered MIME type that matches the given generic name" — matching by MIME top-level type, and deliberately only in the *request* direction so an offer literally named `text` never becomes a wildcard. `wants_text_plain` is the matching question on the synthesis side ("would a `text/plain` answer this request?"), since `is_text_plain` alone says no to `-t text`.
- **`peer.rs`** — `run_connection`: Noise handshake + `Hello` exchange (checks `PROTOCOL_VERSION` and rejects a self-connection via the `SelfConnection` marker error, which dial loops treat as permanent), then reader/writer tasks. `AbortGuard` tears the connection's child tasks down on cancel.
- **`mesh.rs`** — `Mesh`: live peer table keyed by remote node ID. Duplicate connections to one peer are expected (both nodes dial each other); index 0 of each peer's group is the designated sender, the rest are receive-only warm standbys. First connection to a peer fires `connect_tx`, which the engine turns into a resync. A `PeerRole::Paster` lives in a **separate `clients` table**, not in `peers`: `broadcast` and `peer_count` read `peers`, so a one-shot paste client is invisible to them by construction rather than by a filter each new reader has to remember, and it can never land at index 0 of a real peer's group (which would have silently swallowed every send to that peer). `send_frame_to` is the only reader consulting both, so a paster is still reachable for its reply.
- **`sync.rs`** — `SyncEngine`, the brain.
  - **Engine loop:** `run` selects over the local clipboard watch, inbound mesh messages, peer-connect events, and rules-changed pings. Handles echo suppression (compare incoming vs. current hash per selection), debounce, `Direction` (send/receive/both), payload caps, and content filtering. **Ordering everywhere — live updates and reconnect resync alike — is the hybrid logical clock `Version { stamp, origin }`** (`protocol.rs`, held by `ContentState`); higher stamp wins, `origin` (node ID) breaks ties. `Version` travels the wire *as one field* on both `Clip` and `Rules`, deliberately: with the pair loose, a site could compare `stamp` alone, which compiles fine and silently diverges the mesh on a tie. Compare whole `Version`s — construct one only where a stamp is genuinely minted (`tick()`). Password-manager contents (`x-kde-passwordManagerHint = secret`) are dropped before broadcast (and, while `exclude_sensitive` is on, never re-owned). **`Pipeline::{Broadcast, Inbound, Own, Mirror, Serve, Restore, Remember, Recall}` is the single taxonomy of "why is this content moving"**, and `Pipeline::stages()` the one place it turns into transforms; `Provenance` is the deliberately narrower write-only subset (`plan_batch` must not be able to emit "broadcast" as a write reason) and converts into it. Previously the two write pipelines mapped through `Provenance::stages` while the rest were `Stages` constants hand-picked at call sites, so each new consumer went around the mapping — `Serve` was added that way. `Restore` exists because `adopt_restored` ran startup content through `Broadcast`, whose `RulesStage::Record` is the opposite of inert: it appended unseen types, persisted the rules file and pushed the whole ruleset mesh-wide, so a node restarting with an unusual type on its clipboard reverted a rules edit another host had just made. It keeps `Broadcast`'s transforms (so the hash recorded in `current` is one a later local read would reproduce) with `Apply` instead of `Record`. `apply_stages` returns `Result<Hashed, Unavailable>`: the reason nothing survived is a value, because a `--paste` client is told it over the wire and "the clipboard is empty" is a bad answer to "every type you offered is denied by my rules".
  - **Clipboard history (`sync/settled.rs`):** `Settled` owns *both* the per-selection `current` record and the bounded history, privately, in a child module the engine cannot see into — so the only way to move `current` is `set`, which takes the **content** and hands it to the history in the same step. `SyncEngine` no longer has a `current` field. That is `ClipboardIo`'s treatment applied to the other easy-to-forget invariant: five sites settle content today, and a sixth added later that updates `current` and not the history would leave a clipboard the user demonstrably had and cannot find, with nothing logged and no test failing. `reorder` (raise the stamp of content we already hold) is the one exempt door, and it is exempt because it cannot change the hash. Rules the store enforces, each for a failure that was reachable: content already at the front is not re-recorded (a reconnect resync re-settles the current content once *per peer*, and each would otherwise rewrite the newest entry's age); a re-copy moves to the front with a fresh time and selection rather than duplicating; an offer larger than the whole byte budget is refused outright instead of evicting everything and still not fitting; and previews are rendered **on the node**, stripped of control and bidi characters, because clipboard content is arbitrary bytes about to be written to a terminal and a hostile *peer*'s copy must not be able to repaint the pasting host's screen. Two pipelines exist for it. `Remember` is `Broadcast`'s transforms with `RulesStage::Apply`, for a local copy on a node that does not send — which now runs through a pipeline where it ran through none, so `Record` there would let a receive-only node's copies append to and mesh-broadcast its shared rules file; reaching that path at all also needed `SelectionPolicy::remember` in `has_local_sink`, since on such a node the batch otherwise never reads the selection. `Recall` is the restore write, and the one place synthesis is deliberately **off**: back-filling `text/plain` would hand back bytes hashing differently from the id the user asked for, so the restore would land as a *new* entry beside the one they picked. A restore writes through `io.write` (echo-suppressed) and then broadcasts under a fresh `tick()` — restoring is copying — which is why `Message::History`'s `Restore` is awaited **inline** while `List`/`Get` are spawned like `Get`: it mutates `current` and must be ordered against local captures and inbound clips. Every pull obeys the rule that a pull must not expose what a push wouldn't: `history get` runs `Pipeline::Serve`, and a **listing** is filtered too — `listing` builds each row inside `with_rules` through `settled::summarize`, per representation, so a type a peer has denied since the copy leaves that row's types, its size and (if the preview came from it) its preview. Rendering rows from the stored bytes alone was the one pull that had not noticed, and it previewed to any psk holder exactly the content `history get` was answering `Denied` for.
  - **Capture-side features (both optional):** `synthesize_text_plain` back-fills `text/plain` (+`;charset=utf-8`) from a legacy `UTF8_STRING`/`STRING`/`TEXT` atom when none exists, and `take_ownership` re-offers each watched selection so clipmesh owns it (surviving the source app) — and, with synthesis, makes the back-filled `text/plain` paste on the origin host too.
  - **Local selection bridge (`link_selections`):** optionally mirrors the local CLIPBOARD and SELECTION on one host — distinct from `sync_selection` (which syncs each selection across the mesh). Local propagation runs as a deterministic read → plan → execute batch pipeline (`handle_batch`): read each changed selection once into `read` (the batch's whole view of the clipboard, echoes included), a pure `plan_batch` decides every broadcast and every write (each selection written at most once, with `Own`/`Mirror` provenance) up front, then `execute_write` performs them. **The plan names its content instead of carrying it** — an `Action` is `{ target, source }`, where `source` is the changed selection supplying the payload (itself, or the bridge source for a mirrored partner). So `plan_batch` takes only the list of changed *kinds* and copies no clipboard payload to reach a decision; execute looks each one up in `read`. The bridge mirrors only *local* user changes: it reconciles against the partner's actual content (so an out-of-band drift is re-mirrored), and a concurrent direct change to the partner in the same batch is never clobbered (direct-change-wins, expressed structurally in `plan_batch`).
  - **Echo suppression of the engine's own writes:** content the engine itself wrote — an inbound mesh apply, content restored at startup, an ownership rewrite, or a bridge mirror — is recorded by `ClipboardIo` and its watch echo is dropped one-shot during `handle_batch`'s classification, so engine-written content is never re-broadcast, re-bridged, or re-owned (this is what makes propagation terminate). **`clipboard::io::ClipboardIo` owns the backend privately, in a module the engine cannot see into, so `Clipboard::write_offer` is literally unreachable from `SyncEngine`** — the only way to write is `io.write`, which records the marker before writing and rolls it back on failure. A new engine-write path therefore *cannot* forget the record; this was previously a convention enforced only by a doc comment on `write_selection`, and the failure mode is an echo storm. Same treatment `Hashed` gives stale hashes. **The read half is structural too:** the marker must be consumed by exactly one reader (the batch classifier) and by no other, so that choice is a *method* — `io.read_classified` reads and consumes, returning an `Origin::{User, Echo}`; `io.read` never consumes. There is no free-standing "take the marker", so a new reader cannot land on the wrong side of a rule whose only symptom is a mesh that never settles. A mesh-synced mirror target is broadcast **directly** by `plan_batch` (not via its echo), so a synced partner is still fed to the mesh like any other local change. See `docs/superpowers/specs/2026-06-20-bridge-write-consolidation-design.md`.
- **`clipboard/`** — see `clipboard/CLAUDE.md`.
- **`client.rs`** — `ask`: dial a node as a `PeerRole::Paster`, send one message, wait for the reply `take` accepts, with a timeout. Extracted when `history` needed the same loop `paste` had; a second copy would have duplicated four decisions that each look like style and are not — driving the connection **inline** so returning tears its reader/writer down, sending only **after** the connect event (the writer is live by then, and the event carries the node ID, so the send is targeted rather than a fan-out that reaches one peer by accident), surfacing the **connection's own** error rather than a timeout when it dies early, and ignoring inbound messages that do not answer this question. `tests/paste.rs` asserts on the word "within" in the timeout message, so that wording is load-bearing.
- **`paste.rs`** — the `wl-paste` impersonation mode (`--paste`, or a `wl-paste`-named symlink).
  - **Fetch mechanism:** `fetch_offer` dials a node via `peer::run_connection` (a throwaway `Mesh` + a random node ID) announcing itself as `PeerRole::Paster`, then **asks**: `Message::Get { kind, want }`, answered with `GetReply`. `fetch_from_any` races `fetch_offer` across every target via a `tokio::task::JoinSet` and returns the first that responds; `resolve_targets` makes the default (no `--node`) every configured peer, `--node` a single one.
  - **Why a request, not the old push-scrape:** it used to take whatever `Clip` the node happened to push on connect. That cost the serving node a full resync per `wl-paste` (a rules snapshot plus a live capture of *every* synced selection — on Wayland one connection per advertised MIME type), transferred the whole offer even for `-t text/plain`, and could only ever report a timeout listing four unrelated causes, because the client had never asked anything. `GetWant::{All, One, TypesOnly}` (from `narrowing`) lets the node send only what the invocation needs, and `GetResult::{Offer, Types, NotOffered, Unavailable}` lets every failure name itself (`interpret`/`explain`). `Unavailable::{NotSynced, Empty, Sensitive, Denied, TooLarge, Unservable, Unreadable}` are the outcomes the serving node's pipeline already distinguishes — it logs a different line for each — so returning the reason as a value is what lets the asking side say something true instead of "empty" for all seven. `Unservable` ("types advertised, but the read produced no representation") is split out of `Empty` because the Wayland backend enforces `max_payload_size` *while reading* — `assemble_offer` skips an over-budget representation — so an oversized image reaches the engine as an empty offer, having never reached `cap_to_payload_size`. That made `TooLarge` unreachable on the real backend and reported a full clipboard as an empty one. `resync_on_connect` is no longer a paste prerequisite; only `p.send` (direction + `sync_selection`) gates what a node will serve.
  - **The narrowing reaches the backend, not just the wire.** `serve_get` maps `GetWant` onto `Clipboard::list_types` / `read_offer(only)`, so `-l` reads no representation contents at all and `-t` reads exactly one. Narrowing only the reply would leave `wl-paste -l` pulling a 30 MB image off the compositor — one connection per type — to print a list of names. `listing_types_reads_no_representation_contents` pins this by gating content reads in the mock and requiring the answer anyway.
  - **But every request starts from the advertised *names*, because narrowing the read destroys two decisions.** A narrowed read filters the offer down before the pipeline sees it — which strips the `x-kde-passwordManagerHint` marker (`-t text/plain` served a password a broadcast refuses, and `-l` skipped the content pipeline entirely) and strips the legacy X11 atom that `synthesize_text_plain` derives from (the same clipboard answered `text/plain` over the mesh and "not offered" to `-t text/plain`). Both decisions are answerable from names, so `serve_get` lists types first — one names-only roundtrip, no contents — and then: `serving_is_sensitive` gates *every* shape of request before any content is read (reading only the tiny hint representation, and only when it is advertised, so ordinary content pays nothing); `serve_source` picks the atom to read when the requested `text/plain` would be synthesized rather than offered; `narrow_to` trims the reply back to the request afterwards. The type list is then reused by the failure path instead of being fetched again. (The sensitivity gate has a KNOWN GAP documented on `serving_is_sensitive`: `paste::get_contents` opens a fresh connection per representation, so the hint and the content never come from one snapshot of the selection. It closes with the same in-tree data-control read the `Initial` gap in `clipboard/watch.rs` needs.)
  - **Narrowing is an optimization, never a change of answer**, and `text_plain_source` is what makes that true: **one names-only predicate** for "would the synthesis stage back-fill `text/plain` here, and from which atom", consumed by all three sites that ask — the stage itself, `serve_source`, and `served_names`. They each used to answer it separately and disagreed about one clipboard: `-l` and `narrowed_failure` read the *advertised* names, which by construction never contain a synthesized type, so a node with `synthesize_text_plain` on and only `UTF8_STRING` copied announced no `text/plain` while happily serving one to `-t` and to the mesh; and `serve_source` tested whether the *requested* type is advertised where the stage tests for *any* `text/plain*`, so `-t text/plain;charset=utf-8` served bytes derived from an atom that a full pull does not offer at all. `served_names` (advertised + synthesized, then rule-filtered) is what `-l` and `narrowed_failure` both answer from.
  - **`NotOffered` is emitted only when the requested type really is absent** from what this node would serve — `narrowed_failure` checks that against `served_names` rather than assuming it. Collapsing every narrowed failure into `NotOffered` produced replies that listed the requested type as available while claiming it was not offered, and discarded the `Unavailable` reason the un-narrowed path reports correctly.
  - **A query must not record.** Serving uses `Pipeline::Serve`, not `Pipeline::Broadcast`: same content filters (a pull must not expose what a push wouldn't), but `RulesStage::Apply` instead of `Record`. `Record` appends unseen types, persists the rules file and broadcasts it mesh-wide — so serving through it would let any paster make this node rewrite its rules and push them to every peer.
  - **Output & wiring:** pure helpers (`select_type`/`list_types`/`render`/`output_bytes`) decide the output; `run` wires `Config::load` and the wl-paste flags, writing raw bytes to stdout. `main` detects the mode (argv[0] or `--paste`) before the daemon flag loop. `PasteArgs::parse` accepts **both getopt attached-value spellings** — `--type=text/plain` and `-ttext/plain` — because the drop-in symlink is told to replace a tool that takes both, and rejecting one breaks existing scripts with an error naming a flag they know works. The short form splits by *position* (a short option is two characters, the rest is the value), not by an `=`, which would mangle `-ttext/plain;charset=utf-8`.
- **`history.rs`** — the `clipmesh history` subcommand (`list` / `get <id>` / `restore <id>`), a one-shot client over `client::ask` like paste mode. Its default target is **this host's own daemon** (`Config::local_addr`, which turns a wildcard *bind* address into the matching loopback, since `0.0.0.0` is not something a client can dial), and `--node` points it at a peer. Deliberately **not** paste's "race every configured peer" default: a paste asks for a shared value — the mesh's current clipboard, where whichever node answers first is as good as another — while a history is a per-node fact, so racing would answer with an arbitrary host's history and `restore` would write the wrong machine's clipboard. An entry can be named **two ways, and the node decides which** (`Listing::resolve`): a run of digits is a row number, anything else is a prefix of the content hash. Both halves of that are load-bearing. Digits-first, because the other way round `restore 3` would be ambiguous most of the time — a sixteenth of all ids start with `3`. And digits *never* fall through to the id search when the number is out of range, because every decimal digit is also a hex digit: a stale `restore 23` against a history that has since shrunk would become a prefix search, land on whichever entry starts `23`, and broadcast it mesh-wide reporting success. The price is that an id whose printed prefix is all digits (about one in forty) is namable only by its row number — which is on the same line. Both exist because they fail differently: the number is what a human retypes, but it is a position and the CLI is one-shot, so a copy landing between a `list` and a `restore` shifts the rows below it; the id is derived from the content, so the worst it does is name an evicted entry, which is a typed failure. `listing()` is the single numbering all three requests share — resolving `get 2` against a different order than `list` printed would hand back a row the user never saw. `Listing` keeps *both* lists on purpose: a **number** is a position, so it indexes the filtered `rows`, while an **id** names content and so is matched against `all`, the unfiltered entries. Resolving ids against `rows` alone turned "every type in it is denied" into "no such entry" the moment one other entry was still servable, sending the user after an eviction that never happened — the exact swap `Filtered` exists to prevent. `-t`/`-n` on `get` accept both getopt attached-value spellings, as paste's do, because `get` *is* `--paste` pointed at an older clipboard and a flag that works on one and not the other is a trap.
- **`mime.rs`** — `MimeRules`: a **program-managed** TOML file (via `toml_edit`). Per-type allow/deny with case-insensitive globs (most-specific match wins, deny-by-default). clipmesh auto-appends unknown types, sorts on save, and stamps a `[clipmesh]` version table so the file can be shared mesh-wide under whole-file last-writer-wins (`share_mime_rules`). The built-in `TEMPLATE` carries the default rules — the common text/image allows plus the deny globs (`JAVA_DATATRANSFER*`, `x-special/*`, …) that stop per-transfer atom names accumulating forever — and **`examples/mimetypes` is generated from it** (`render_example`, pinned by a golden test, same arrangement as `examples/config.toml`). Never hand-edit the example; change `TEMPLATE`, then `CLIPMESH_REGEN_EXAMPLE=1 cargo test --lib example_mimetypes_matches_template`. `reload_if_changed` compares **content, not mtime**, so clipmesh's own writes don't trigger a reload→rebroadcast loop. **`parse_body` is the module's only door from text to document**, and promotes an inline `rules = { … }` / `clipmesh = { … }` to the header form: an inline table is valid TOML meaning exactly the same thing, but `toml_edit` stores it as a *value* that `Item::as_table` cannot see — so every lookup missed the table (the node fell through to `unknown_mime` and silently stopped syncing everything), and `table_mut`'s `is_table()` guard is blind the same way, so the first unseen type replaced the user's ruleset with an empty one and `share_mime_rules` pushed it to every peer. Collapsing the two flavours at the single parse site is what keeps the eight-odd read and write sites from each having to remember the distinction. Relatedly, `set_rule` writes to an existing key **whatever its case**: `remove_matching` spares a case-insensitively equal entry so `apply_glob` can flip it in place, so inserting the pattern verbatim left two rules for one type, and the deny tie-break made `--allow utf8_string` (against the template's `UTF8_STRING`) a silent no-op. **Two constructors, because healing is destructive:** `MimeRules::open` never writes and returns a `RulesFileState::{Missing, Empty, Malformed, Unreadable}` when it can't load, while `load` is `open` plus "rewrite everything except a file we merely failed to read". The CLI (`--rules`/`--allow`/`--deny`) uses `open` so it cannot clobber a file it couldn't parse — that guard used to live in `main.rs` as a second read and a second `toml_edit` parse, outside the abstraction, which left both a TOCTOU window and a classification that could disagree with `read_file`'s. All writes funnel through one private `persist_body`, which uses `fsutil::write_atomic` (temp file + rename onto the resolved symlink target): this file is rewritten on every unseen MIME type and is shared mesh-wide, so a truncated half-file from a crash or full disk would be adopted by peers.
- **`config_template.rs`** — the canonical config-file template + the `--sync-config` normalizer: one ordered list of `Block`s describes every option, its comment, and its default; `render` emits the file overlaying the user's present values (options the user set stay active, the rest become commented defaults). `examples/config.toml` is **generated** from the same template and pinned by a golden test — never hand-edit the example (the test fails the build); change the template, then `CLIPMESH_REGEN_EXAMPLE=1 cargo test --lib example_config_matches_template`. Adding a config option means adding a `Block` here too: `render` only emits keys that have one, so a missing block would make `--sync-config` silently drop that option from a user's file. `every_config_option_has_a_template_block` enforces this against `config::RAW_CONFIG_KEYS`, and `sync_config` refuses to write a lossy file rather than trusting the test alone. Each optional block declares its shown value as `Shown::Default` — a *promise* that uncommenting the line changes nothing, enforced by `commented_defaults_are_the_parsers_defaults`, which activates the whole template and compares the parsed `Config` against a minimal one — or `Shown::Sample` (illustrative; `peers` and `mime_rules_file` have no literal default to print, and their comments say so). That split exists because both had silently drifted from the real defaults with the golden test still green. `key_defaults` is the single exhaustive scan of `TEMPLATE`, with no `_` arm, so a new `Block` variant stops the build rather than falling out of a derived set. Two mechanisms keep that key list honest, because either alone has a hole: `Config::from_toml` destructures `RawConfig` **without a `..` rest pattern**, so a new field is a compile error, and `raw_config_keys_matches_the_struct` pins `RAW_CONFIG_KEYS` to serde's own field list (captured from `deserialize_struct`, not scraped from an error message) so satisfying the compiler by editing only the destructure still fails.
- **`config.rs` / `fswatch.rs`** — `Config::load` parses TOML and defaults `mime_rules_path` to sit beside the config. `default_config_path` honours **`$XDG_CONFIG_HOME`** (absolute values only, per the basedir spec), matching `install.sh`, which writes the config, psk and systemd unit under `${XDG_CONFIG_HOME:-$HOME/.config}` — with the path hardcoded to `~/.config` the installer reported success and the unit then restart-looped on a config it could not find. `install.sh` likewise rewrites the copied `examples/config.toml`'s `~/.config/clipmesh/` paths to the directory it installed into. `fswatch` is an inotify watcher (dedicated thread) over both files, and is symlink-aware (follows a symlinked config/rules file to its real target). A **config** change makes the process exit cleanly so a supervisor restarts it (most settings can't hot-apply — this requires the systemd unit or any restart-on-exit supervisor); a **rules** change reloads in place. **`fswatch` only reports, though — it never exits.** Both arms now have the same shape: the rules change reloads and pings, the config change is sent to `main`, which owns `ConfigChange`/`config_change_action` and decides to restart. A watcher thread is the wrong place to end the process, and deciding it there also forced this module to parse the config (`use crate::config::Config` is gone). The watches sit on the *directories*, so a re-stow (`rm -rf` + recreate) makes the kernel drop them and report `IN_IGNORED` — which carries no file name and so must be handled before the name guard, or the entries keep a dead descriptor and `read_events_blocking` blocks forever on an empty watch list instead of erroring, leaving the process permanently deaf with nothing logged and no restart. It re-registers in place, or returns the error so `supervise` retries on its backoff until the directory is back.
- **`backoff.rs`** — the shared exponential-backoff helper (`next_delay`), the watcher restart policy (`RESTART_*` / `watcher_restart`), and `supervise`, the restart *loop* both long-lived watcher threads run on: it owns the timing, the "was that run healthy?" reset and the restart log, so `fswatch` and `clipboard::watch` supply only the attempt (returning `ControlFlow::Break` to retire the watcher, as the clipboard watcher does when the engine is gone). The dial loop in `node.rs` intentionally keeps its own schedule: a much lower cap (5s, so a returning LAN peer reconnects fast), a longer healthy threshold, and jitter to desynchronise simultaneous mesh reconnects.
